{# ── Claude Code ── #}

1 이 폴더에서 빠른 연결 명령 실행

위 2단계의 명령 하나면 됩니다. 수동으로 할 경우:

pip install git+https://github.com/senghan1992/my-viking.git
jv hook install --url {{ base }} --key jv_... --project {{ project.slug }}

✓ 확인: jv hook check — SessionStart 등 4개 이벤트

2 Claude Code 로 작업 시작

이 폴더에서 평소처럼 Claude Code 를 쓰면 끝입니다. 자동으로 일어나는 일:

  • 세션 시작 → 지난 작업 브리핑 자동 주입
  • 질문마다 → 관련 지식만 골라 주입 (검증 전은 단정하지 않도록 표시)
  • 작업 종료 → 지식 자동 증류·기록, 틀린 지식은 '검증 필요'로 강등
{# ── pi ── #}

pi 전용 확장을 설치하면 브리핑 주입·자동 증류·viking_search 같은 도구를 세션에서 쓸 수 있습니다. pi 세션은 기본적으로 연결되지 않습니다(자유 사용) — /myviking connect 또는 /myviking use 로 그 세션만 이 프로젝트에 연결됩니다. 다른 세션에는 영향이 없습니다.

1 빠른 연결 명령 실행 (jv 없으면 함께 설치)

curl -fsSL {{ base }}/install.sh | bash -s -- --url {{ base }} --key jv_... --project {{ project.slug }}

2 pi 재시작 + 이 세션에서 연결

pi 를 껐다 켜거나 /reload 후, 연결할 세션에서: /myviking use(폴더 기본값 적용) · /myviking connect(주소+키 직접) · /myviking switch(저장된 목록). 연결하면 브리핑이 주입됩니다.

3 연결 관리 — 세션마다 자유롭게

  • 터미널: jv pi list · jv pi switch <이름> · jv pi disconnect · jv pi remove <이름>
  • pi 안에서: /myviking (상태/목록) · /myviking use · /myviking switch · /myviking connect · /myviking disconnect · /myviking remove
{# ── jcode ── #}

jcode(J-Code)는 훅·스킬·MCP가 모두 지원되므로 질문→답 자동 기록까지 pi 와 같은 수준으로 붙습니다. 연결은 폴더 단위입니다 — 프로젝트 폴더에서 실행하세요.

1 빠른 연결 명령 실행

curl -fsSL {{ base }}/install.sh | bash -s -- --url {{ base }} --key jv_... --project {{ project.slug }}

설치되는 것: ① ~/.jcode/config.toml 의 [hooks] (turn_end 자동 기록), ② ~/.jcode/skills/myviking/SKILL.md, ③ ~/.jcode/mcp.json. 이미 직접 설정한 훅 이벤트는 건드리지 않습니다.

2 jcode 재시작

훅 설정은 config 를 다시 읽을 때 적용됩니다 — jcode 를 껐다 켜세요. 세션이 시작되면 스킬이 지시하는 대로 jv brief 를 실행하고, 턴이 끝날 때마다 자동 기록됩니다.

3 확인·전환

  • jv jcode check — 훅·스킬·MCP·서버·프록시 한 번에 확인
  • jv jcode list · jv jcode switch <이름> · jv jcode disconnect · jv jcode remove <이름>
{# ── MCP ── #}

MCP 를 지원하는 에이전트(Cursor·Codex 등)는 JSON 하나로 연결됩니다. 브리핑·검색·기록을 도구로 호출할 수 있지만, 세션 자동 캡처는 없습니다.

1 jv 설치 후 에이전트의 MCP 설정에 추가

설정 파일(예: Cursor → Settings → MCP, Codex → mcp.json)에 아래를 붙여 넣고 MYVIKING_KEY 에 방금 발급한 키를 넣으세요:

{
  "mcpServers": {
    "myviking": {
      "command": "jv",
      "args": ["mcp"],
      "env": {
        "MYVIKING_URL": "{{ base }}",
        "MYVIKING_KEY": "jv_...",
        "MYVIKING_PROJECT": "{{ project.slug }}"
      }
    }
  }
}

2 확인

"지식 브리핑 줘"라고 물어보면 viking_brief 도구가 동작합니다. 도구: viking_brief · viking_search · viking_remember · viking_score

{# ── 셸 / 수동 ── #}

어떤 에이전트든 터미널 명령으로 도서관을 쓰는 방법입니다. 자동화는 없지만 가장 확실합니다.

1 jv 설치

pip install git+https://github.com/senghan1992/my-viking.git

2 자주 쓰는 명령

시작할 때 브리핑 / 막혔을 때 검색 / 알게 된 규칙 기록:

jv brief -u {{ base }} -k jv_... -p {{ project.slug }}
jv search "배포 방법" -u {{ base }} -k jv_... -p {{ project.slug }}
jv remember "릴리스는 화요일에만" --content "배포 동결은 월요일." -u {{ base }} -k jv_... -p {{ project.slug }}

3 팁

자주 쓰는 명령은 에이전트의 지침(AGENTS.md)에 넣어두거나 셸 별칭으로 만들어 두면 편합니다. jv --help 로 전체 명령을 볼 수 있습니다.

{{ icons.icon('copy') }} 에이전트 지침 (AGENTS.md 에 붙여넣기)

지식이 '확인된 사실'과 '검증 전'으로 나뉘어 주입됩니다. 검증 전은 단정하지 말고 확인하세요.

이 프로젝트는 myviking 지식 도서관에 연결되어 있습니다.
- 세션 시작 시 주입되는 브리핑과 질문마다 주입되는 '관련 지식'은 이전 작업의 축적입니다.
- ⟨검증 전⟩(fresh) 지식은 사실로 단정하지 말고 코드/문서로 확인하세요.
- 확립(established) 지식이라도 최근 결과와 어긋나면 "검증 필요" 경고로 표시됩니다.
- 새로 정한 규칙·함정·결정은 `jv remember "제목" --content "내용"` 또는 도구로 남기세요.
- 내 답변이 틀렸음을 알게 되면 같은 제목으로 바른 내용을 남겨 교정하세요.
