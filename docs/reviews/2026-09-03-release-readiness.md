# 배포 준비도 평가 — 2026-09-03

> 질문: "지금 상태 그대로 사람들에게 배포해서 써 보라고 권할 수 있나?"
> 이 문서는 그 질문에 대한 냉정한 답과, 답을 바꾸기 위해 같은 날 고친 것, 그리고
> 여전히 남은 한계를 적습니다. 마케팅 문구가 아니라 검증 기록입니다.

## 결론

**권할 수 있는 범위: 혼자 또는 소규모 팀이, Claude Code 훅으로, 자기 서버에 붙여 쓰는 것.**
아래 조건을 지키면 "먼저 지식창고를 보고, 없으면 평소처럼 일한다"가 실제로 성립합니다.

- 중요한 규칙·명령·함정은 `jarvis_remember`(또는 대시보드)로 직접 넣는다. LLM 없이는
  자동 증류가 "질문 → 답 첫 문장" 사례만 남기고, 그건 ⟨미확정⟩ 참고 자료다.
- 품질을 원하면 서버를 띄운 뒤 `ANTHROPIC_API_KEY` 와 임베딩 프로바이더를 넣는다
  (`up.sh` 가 끝날 때 현재 수준을 알려 준다).
- 서버는 루프백/VPN/HTTPS 중 하나로만 연다 (README 시나리오 표).

**아직 권하기 어려운 범위:** Cursor/Codex 같은 훅 없는 클라이언트를 주력으로 쓰는 경우
(에이전트가 도구를 호출해 줘야 기록된다), 그리고 실제 임베딩 프로바이더를 붙인 대규모
저장소(수천 건) — 보정은 실측했지만 한 모델(e5-small)로만 했다.

## 발견하고 고친 것

### 지식창고 오염 (이게 "제대로 동작 보장"의 핵심이었다)

| 결함 | 근거 | 고친 것 |
|---|---|---|
| 컨텍스트 압축 요약("This session is being continued…", 1만7천 자)이 사용자 질문으로 기록됨 | 실제 대화록 | `_is_person_prompt`: 압축 요약·`[Request interrupted`·`promptSource=system`·`isMeta`·사이드체인 제외 |
| API 오류 자리표시자(model `<synthetic>`, `isApiErrorMessage`)가 답변으로 기록됨 | 실제 대화록 | `_is_real_answer` |
| 사용자 불만("서명 검증이 항상 실패해")이 "항상" 때문에 `conventions` 규칙으로 승격 | 감사 A | `_is_complaint`: 실패 서술 문장은 규칙 후보에서 제외 |
| 인사말이 세션으로 기록되어 "최근 작업: 안녕", 점수 0.62 | 감사 A | `commit()` 이 chatter 를 기록하지 않음 (`skipped: chatter`) |
| "이 함수 리팩터링해줘 → 3개로 분리" 같은 대상 없는 작업이 메모리로 승격 | 시뮬레이터 | 지시어 + 작업 지시일 때만 사례 생략 (질문은 유지) |
| 제목이 조사에서 잘림 (`cases/테스트는`) | 감사 A | 마지막 단어의 주격/목적격 조사 제거 |
| git 저장소가 아닌 폴더(/tmp)가 `tmp` 프로젝트를 자동 생성 | 감사 A | 미생성 + 세션당 1회 안내. `--project <이름>` 으로 고정 가능 |
| Stripe(`sk_live_`)·Google OAuth(`GOCSPX-`)·Slack app(`xapp-`) 키가 원문 저장 | 감사 A | 패턴 추가 (Stripe/whsec/HF/SendGrid/Shopify/DO 포함) |

### 검색·주입 (요청: "없으면 그냥 일반 에이전트처럼")

| 결함 | 근거 | 고친 것 |
|---|---|---|
| 저장소 ≤8건이면 무관 프롬프트에도 전량 주입 ("hello" 에 5건) | 시뮬레이터 | `min_relevance` 절대 게이트 (근거 = 벡터 우위 + 어휘) |
| 어휘 검색이 조사·어미 변형을 못 잡음 ("재시도해도"↔"재시도하지") | 시뮬레이터 | `ko_stem` 접미사 제거 + 접두 매칭, 불용어 |
| 2음절 접두("로그인"→"로그*")가 무관 지식을 끌어옴, 정확+접두 이중 계산 | 감사 B | 맹목 단축 제거, 항당 절 1개, 짧은 라틴은 정확 일치 |
| 실제 임베딩 모델에서 무관 문장 코사인 0.83 → 게이트 무력화, 병합 문턱 0.82 초과로 **메모리 소실** | e5 실측 | 모델 기준선 자동 측정·보정 (`Embedder.calibrate`), 후보 중앙값 대비 우위로 게이트 |
| 답 캐시가 작업 지시("이 함수 리팩터링해줘")에 이전 답 재사용 | 시뮬레이터 | `reusable_question`: 작업 지시·지시어·인사 제외 |
| 그 필터가 "it/that/here" 까지 잡아 정상 질문의 학습·캐시 차단, 의문사 섞인 작업 지시는 캐시 | 감사 B | 지시어 정규식 축소, 작업 판정이 우선 |

## 남은 한계 (문서에도 적음)

1. **Docker 경로는 이 환경에 docker 가 없어 `--dry-run` 테스트로만 검증.** 깨끗한 머신에서
   `deploy/up.sh --domain` 실행 확인은 사용자 몫으로 남아 있다.
2. **임베딩 보정은 모델 한 개로 실측.** OpenAI·bge-m3 에서는 `/health` 의
   `embed_similarity_floor` 와 `/prepare` 의 `relevance` 를 보고 `min_relevance` 를 조정해야
   할 수 있다.
3. **LLM 없는 자동 증류는 얕다.** 정답지 자가 갱신(§6 (B) 두 속도 교정)은 규칙 카테고리
   메모리 사이에서만 일어나고, 사례(`cases`) 는 서로를 대체하지 않는다. 확실한 교정은 같은
   제목의 `remember`.
4. **주입 안내문이 본문보다 길다** (약 170토큰). 줄일 여지가 있다.
5. **비슷한 질문의 사례가 여러 건 실릴 수 있다** (제목이 다르면 중복 제거가 안 된다).
6. 훅 상태 디렉터리가 서버와 무관하게 머신 전역(`~/.myviking/hook-state`)이라 `--check` 의
   실패 기록에 다른 서버의 것이 섞일 수 있다.
